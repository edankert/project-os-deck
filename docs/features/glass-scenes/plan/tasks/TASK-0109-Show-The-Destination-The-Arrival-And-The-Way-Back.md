# Show the destination, the arrival and the way back

The window's half of the handoff. A person sees where a note is going and which act it is before they let go, sees it arrive in the other window, and can send it back. TASK-0108 supplies the states; this task draws them. It was built in commit `f80339f`. The arrival in a desk window was changed in `5f706a5` and `9379a0c`. Commit `9d94fa0` built the seven things the first close-out found missing and fixed two defects. Commit `972985f` drew the chooser's sentence whole, and commits `5d5b38f`, `39915fe` and `972ce73` fixed what the independent review found in the handoff.

**Where it stands, 2026-10-02.** The task stays `doing`. Two boxes are open, and both need a second display: the strip's entry for an empty display has not been seen on a screen, and no display has been unplugged during a handoff. Everything else is ticked. In the pass at `e86b2e4` one thing was seen in a picture and asserted by no check: in the keyboard chooser the sentence saying what a move does was cut short in a window 1100 pixels wide. Commit `972985f` draws it whole above the status line, and the walk's chooser check now requires each sentence to be drawn whole; that check has not been run in a pass this note cites. The evidence is the scripted walk `glass-handoff`, run in a Linux container with one display at commit `e86b2e4` with 33 checks, all of which held, on this repository and on a copy of `your-trainer`, and the smoke run at the same commit ([[TST-0076-Scenes-And-Handoff-Are-Walked-With-A-Real-Pointer]]). A quoted check below is one of that walk's unless the smoke run is named, and a quoted test is one of `desktop/tests/handoff.test.mjs`.

**After the independent review, 2026-10-02.** The reviewers ran no window, so nearly everything in this task was marked *not checked*: the strip on screen, the reading position on arrival, the mark, the message and reduced motion. By reading the code both found that a "send back" which failed could not be pressed again: the next press was told the note "did not arrive here from another window". That is fixed in `39915fe`, and the handoff walk was given a step for it: the main window is kept busy, the send back is not answered, the desk window says so and still offers "send back", and the next press takes the note back. A second send of a note that is still on its way is now refused with a sentence (`5d5b38f`). A window that answers after the source stopped waiting no longer marks or announces an arrival (`972ce73`); no check covers that. One thing a reviewer raised is kept as it is: a second arrival replaces the first one's line. The new step has not been run in a pass this note cites, and no box is ticked or unticked for it.

## Notes

**How the act is chosen during a drag.** A document goes only where it is released on a named entry of the strip. A fast release past the edge does not send a document anywhere: the speed of a throw is read for a card from the field only, and such a card carries no act and is shown, not moved. This is read in the two drag handlers in `glass.ts`.

**"Send back" after "Also show in".** The source already has the document, so there is nothing to move, and the build finds and raises it. That reading is flagged to Edwin with the other readings in ADR-0007.

**Two windows with the same name.** An entry names a window by what it carries and its display, so two desk windows on one display both read "the desk on …", whichever view each draws. By reading `sendTo`, the keyboard chooser keeps one answer per name, so the second such window cannot be chosen there. No run had two desk windows open at once.

**A second arrival replaces the first one's line.** The line above the status line is one element and shows the latest arrival. Each document that arrived keeps its own mark, and `S` on it still offers "Send back". A reviewer raised this without looking further, and it is kept as built (FEAT-0023, decision 20).

**A note that is on its way cannot be sent again.** Until the destination answers, any second send of that note is refused, whatever the act and the place, and the window says where the note is already going (commit `5d5b38f`). No walk sends a note twice; the rule is tested without a window.

**A "send back" that fails can be pressed again.** The button and `S` keep offering it until the note is shown back in the window it came from (commit `39915fe`).

**A destination that answers too late shows nothing of an arrival.** When the source has stopped waiting, the note has been taken off the destination desk again. The window reads the answer to its acknowledgement and neither marks the document nor shows the line (commit `972ce73`). Nothing checks this: no node suite loads the renderer, and no walk looks for it.
